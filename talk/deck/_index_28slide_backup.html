THE THING THAT MAKES IT FAST IS THE THING THAT MAKES IT HONEST

Definition

An agent confidently asserts something false about the world — and then acts on it.

Not a refusal. Not a hallucinated poem. A false claim about state that becomes an action.

Five flavors, one mechanism

FOUR ARE RELIABILITY BUGS. THE FIFTH IS WHAT AN ATTACKER REACHES FOR.

The cost isn't tokens

It's blast radius.

deploy_prod()

issue_refund()

grant_iam_role()

A privilege was granted on a precondition that was never true.

Where our defenses actually live
Three families of defense

Neural guardrails

Llama Guard, NeMo, classifiers

“Does this text look bad?”
Probabilistic — and itself a target.

Policy engines

OPA / Rego, IAM

“May the agent CALL this?”
Authorization, not verification.

Formal methods

Constrained decoding, SMT, Lean

“Is the output well-formed?”
Right idea — but offline.

The question none of them asks

Did the action's claimed effect actually happen — are its preconditions true?

The gap

Almost nobody is verifying action semantics against world state, in the loop, as a security control.

People do verification — offline. Nobody's doing it on every action.

The layered world model

The part that can be wrong is the last resort.

L1
Symbolic — exact precondition/effect match confidence 1.0 or 0.0 · nothing to argue with · handles 100% of planning here
L2
Learned — statistics from execution logs confidence grows with observation count · trusted, but not proof
L3
Generative — the LLM, for genuinely novel actions queried once to bootstrap, then cached · 50 one-time calls, then zero

UCB1 SEARCH ON TOP · THE LLM IS QUERIED LAST, NOT FIRST

The shape of the fix

Three properties a sampled model cannot give you

Reliability

The failure mode changes. A wrong model acts confidently. This one refuses — and refusal is recoverable in a way a bad deploy is not.

100% vs 92% (LATS) / 64% (ReAct) — and it degrades to “no” rather than to “oops”

Reproducibility

Same input, same plan, every run. Zero variance across seeds. This is what makes an agent testable at all.

Regression-test it · bisect a behavior change · replay an incident and get the same answer

Auditability

Every refusal names the exact missing fact — not “the model seemed unsure,” but tests_passed ∉ ground_truth.

A structured compliance artifact, emitted for free, on every single action

You cannot get any of the three from sampling. Not at temperature 0 — that reduces variance, it doesn't create a checkable record.

Where this goes

The harness is becoming the product.

A place to check, not recall

A world model gives an agent somewhere to verify a claim instead of retrieving a plausible one.

Evidence that compounds

The graph is shared and persistent — one agent's verified transition becomes every agent's prior. A fleet accrues an asset, not N context windows.

The real bottleneck

Somebody has to author the specs. That's the open problem — and the one I think is worth working on.

What to do Monday
01
Formalize your high-blast actions as preconditions and effects start with the irreversible ones — deploys, payments, privilege grants
02
Check preconditions ⊆ ground_truth before every irreversible action a set-containment check — it costs nothing
03
Log every refusal as a security event the mismatch is the signal you've never had before
